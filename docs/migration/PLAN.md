# VFX Launcher Rust migration plan

Planning baseline: 2026-11-05, checkout `/home/npittas/VFX-Launcher-v2`, branch `migration/rust-egui-suite`, shared isolation. This is a source-based implementation plan, not an implementation or runtime verification report. Read with [CONTRACTS.md](CONTRACTS.md) and [RESEARCH-INVENTORY.md](RESEARCH-INVENTORY.md). Reconciliations below supersede conflicting inventory claims; the inventory itself is unchanged.

## Scope and execution

Port VFX Launcher plus FolderStructurer, CleanIncomings, SearchFolderStructures, File-Extention-Copier and NAS-Backup into one Rust crate at `rust/`, leaving the Python application usable. No GalleryBrowser, KAssetManager, embedded Python runtime, provider authentication implementation, or generic plugin framework. One binary provides the GUI and backup job/dry-run commands. Linux and Windows are the initial behavior targets; macOS is not a release commitment.

This task writes only these two planning documents. No tests, test creation, builds, dependencies, application launches, production data access, reference-clone modifications, commits, pushes or PRs. All future packets inherit root AGENTS.md: explicit source scope, hard 10–30 second command limits, project-local artifacts, no global test runs, no test creation without a later assignment. Verification criteria below are future acceptance obligations, not authorization to execute them now. No task should silently exceed these limits.

## Decisions: preserve behavior and make changes explicit

1. **Single crate, simple modules.** egui/eframe UI, rusqlite storage, serde JSON config, native dialogs, standard background threads/channels. No async runtime or service container by default. Feature modules produce plans; only transfers executes project/media file mutations. Storage and config own application persistence; UI owns view state only.
2. **Separate local catalog.** Import legacy DB read-only into a new local SQLite file. Retain old DB, INI, favorites and Python sources unchanged. New catalog uses WAL, foreign keys and a bounded busy timeout only on local storage. Shared SQLite over SMB is not a supported writable mode; network media roots remain supported. A central multi-user catalog would require a later architecture decision, not a promise of safe SQLite locking.
3. **JSON is the new configuration.** Native settings, UI state, clients, templates, patterns, profiles and backup jobs have versioned JSON. Legacy INI/JSON/template inputs have explicit importers; failed imports leave previous good settings intact. One selected legacy source per import, no silent merging across unrelated installations. QSettings binary geometry/state is not imported; useful portable preferences can be manually recreated. Record that migration limitation.
4. **Identity stays simple.** Default to the imported `admin` record by username, never assume its ID equals 1. Preserve user CRUD and attribution; allow selection of existing user for favorites/history. This is identity selection, not authentication or access control. Provider credentials belong solely to the future external AI harness.
5. **Unified execution, distinct intent.** Projects, structure creation, incoming normalization, extension copy, organizer and backup share validated operation plans. They keep different discovery filters, routing and naming presets. Ordinary copy/move defaults to Skip conflicts; replacement must be explicit. Backup defaults to preserve-existing with numbered names. Remove project means unregister catalog records, never delete its folder.
6. **Safer proposed semantics.** Plans enumerate exact sequence members, reject escaping destinations, guard source/destination identity and nesting, stage copies, revalidate stale metadata and retain move sources until a successful commit. No automatic all-batch rollback or undo promise. Interrupted work is reported per item; retries require a fresh validation.
7. **Useful feature parity, no stale stubs.** Deliver search, favorites/recents, versions, launching, users, logs, structure/template editing, incoming editing and transfer controls, organizer, extension copy and scheduled backups. Archive/Duplicate stubs and unused watchdog/scan interval are excluded from the parity baseline. Surface unsupported imported options as inactive; do not invent a background monitor.
8. **External applications remain external.** Launch argv directly; Linux Nuke command import needs token parsing without shell expansion. Windows Nuke keeps `--nukex`, AEP/AET uses the configured editor; reveal/default-open is platform-specific. Fix Windows-only `.exe` validation for Linux. Media inspection can use installed ffplay/VLC through explicit launch actions. Embedded media player and Nuke socket integration are separate parity decisions below; no claim of preserving them through a simple external-open button.

## Module boundaries and ownership

All paths below are proposed under `rust/`; no Rust files are created by this task. Concrete shared types and invariants are in CONTRACTS. Dependencies flow UI/app → feature modules → paths/discovery/transfers/storage. Feature workers do not call UI; transfers never calls AI. Do not turn this map into a trait per module.

## Remaining decisions and blockers

| Decision | Minimal current default | What remains blocked |
|---|---|---|
| Pi versus OpenCode | Provider-neutral, schema-checked proposals; authentication fully external | Concrete executable/API adapter and live provider parity until harness selection and its capability contract are inspected. No invented common CLI protocol. |
| Shared multi-user catalog | Local catalog, network file roots | Concurrent shared-catalog product requirement, if required; local import is an intentional change from the README's shared-DB claim. |
| Embedded incoming media / Nuke socket integration | External preview actions initially | Full parity disposition needs focused source/product review; do not label migration fully complete while these useful capabilities lack an accepted disposition. |
| Regex/import corner cases | Preserve raw input, explicit unsupported-rule diagnostics | Complete compatibility until extraction helpers and any unsupported Python regex constructs are reconciled. |
| Packaging distribution | One binary, Linux + Windows, no auto-update | Final installer format, signing and distributable validation. Native dialogs and filesystem behavior must be checked on both targets. |
| Legacy UI-state/private settings | Fresh geometry, documented portable preference migration | Exact private `user_settings.json` and platform QSettings migration coverage remains unverified; do not read production state to fill this gap. |

Routine decisions above are recorded, not permission questions. Feature completeness requires all six projects' included workflows, migration reports, safety invariants and accepted dispositions for the real gaps. Shell acceleration, automatic monitoring, broad media browser scope and legacy stub actions are not prerequisite features.
